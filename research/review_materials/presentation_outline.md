# Faculty review presentation

The editable slide deck `review_deck.pptx` accompanies this outline. Present the project as a synthetic research engineering case study, not a real UPI fraud-prevention product.

## Narrative and demonstration

- **Problem:** Transaction scores do not directly describe target completion before intervention; FLAG can debit while BLOCK terminates.
- **Architecture:** Existing Python engines, ledger, two tree detectors, policies, immutable records, independent checkers and local-only safe dashboard.
- **Design:** Keep corrected legacy results separate; new pilot has nine blocks, HVB/GE, five controls, narrow registered mechanism exclusion and benign test strata.
- **Results:** 7,200 campaigns; 3,539 completions; 28,895 evaluated transactions. Show paired cells rather than implying the pooled rate is a real fraud success probability.
- **Failure:** Ordinary benign has zero observed BLOCK, but legitimate GE mimics are blocked 48.278%/12.806%. This is central evidence, not something to hide.
- **Novelty:** Acknowledge prior sequence fraud detection, synthetic finance and RL banking attacks; claim only the auditable implemented combination and bounded failure analysis.
- **Live workstation:** Start a short actual job, inspect logs/exit code, explore one campaign, compare compatible cells and export.
- **Evidence and limits:** Show hashes/checkers/reconstruction and distinguish software verification from scientific or external validation.
- **Submission status:** Author/venue/AI-policy approval and genuine institutional AI/similarity reports remain pending; Gate C HOLD.
